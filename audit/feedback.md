# Audit — Feedback / Communication family (Task 2-e)

Scope: `Badge`, `LinearProgress`, `CircularProgress`, `LoadingIndicator`, `Snackbar`, `Tooltip`, `Banner` (+ `feedback-demos.tsx` + the 7 meta blocks in `src/lib/m3/meta.ts`).
Verification sources: m3.material.io component pages, official reference implementations (androidx Compose material3 `Badge.kt` / `Tooltip.kt` / `ProgressIndicator.kt` / `LoadingIndicator.kt` + tokens, fetched from androidx-main; MDC Web `mdc-tooltip/constants.ts`, `mdc-snackbar/_snackbar-theme.scss`; Flutter M3 `MaterialBanner`). All motion stays on `@/lib/m3/tokens` springs/durations; colors are `m3-*` tokens only; `'use client'` and named-export + `xxxMeta` re-export contracts intact.

Per-component sections: (1) spec, (2) implementation before, (3) deviations, (4) required changes, (5) implemented, (6) remaining limitations.

---

## 1. Badge

**Material spec.** Small badge = 6dp dot; large badge = 16dp min-width/height container, `error` bg with `label-small` `on-error` text, overflow "99+" (default max character count 2); single digit renders as a 16×16 badge (not a dot); pinned to the anchor's top-right. Disabled content 38%.
**Before.** Dot 6px ✓; 16px min-width pill with `label-small` ✓; max=99 → "99+" ✓; but anchor offsets were an arbitrary `-top-1 -right-2`, disabled used `opacity-40`, dot was announced to AT, and the corner-radius question (spec sheet's 4dp vs implementation) was unverified.
**Verified values.** Compose M3 `Badge.kt`: text-badge offsets = 12dp from end / 14dp vertical overlap → 16dp badge overhangs **4px right / 2px top**; icon-only dot offset 6dp/6dp → dot sits **flush in the corner** (`right-0 top-0`); `LargeShape = ShapeKeyTokens.CornerFull` → the *reference implementation* uses full rounding (the Figma spec sheet's 4dp is overridden by the shipped component spec); both dot and text badge kept `rounded-full`.
**Required / implemented.** Offsets per official geometry (`-right-1 -top-0.5` for value badge, `right-0 top-0` for dot); disabled `opacity-38` (cross-cutting 38% token); dot `aria-hidden="true"` (decorative); doc comment + meta updated (anatomy, states 38%, showDot/disabled prop docs).
**Remaining limitations.** Spec-sheet 4dp corner vs Compose `CornerFull` documented in meta as "full corners per official reference" — a Figma-literal reading would use 4dp; value badge has no built-in accessible description (callers label the anchor, as the demo does).

## 2. LinearProgress

**Material spec.** Track 4dp `surface-container-highest`, rounded-full; active indicator rounded-full; **M3E determinate = 4dp gap + 4dp stop dot** at track end (`LinearProgressIndicatorTokens.TrackActiveSpace = 4dp`, `StopSize = 4dp`, verified in Compose tokens); indeterminate = two sweeping bars; M3E wavy variant with slide + amplitude pulse; `role=progressbar` with `aria-valuemin/max/now`, no `aria-valuenow` when indeterminate.
**Before.** All core geometry was correct (spring fill capped at `calc(100% - 8px)` = 4px gap + 4px dot; two-bar indeterminate; wavey slide+pulse; correct ARIA). Deviation: the **wavy variant rendered no flat track** (official M3E wavy keeps the 4dp track visible behind the wave); `aria-label` was undefined when no label prop was passed.
**Required / implemented.** Added the flat 4dp `surface-container-highest` track line behind the wave (both wavy modes); `aria-label={label ?? "Loading"}`; meta anatomy updated (track visible in flat *and* wavy variants; "4px dot after a 4px gap").
**Remaining limitations.** Wavy determinate approximates the official "wave flattens toward the head, then 4dp gap + dot" by hard-clipping the wave container at `value%`; the indeterminate sweep speed (durations.medium2 ×3) is a token-multiplier approximation of the M3E expressive cadence.

## 3. CircularProgress

**Material spec.** 48dp default, 4dp stroke, track `surface-container-highest`, active `primary`, round caps; M3E determinate has the stop indicator: **4dp dot with a 4dp gap**, and per the Compose reference the dot is **fixed at 12 o'clock** (the track end), not riding the arc head; indeterminate arc grows to ~270° and contracts while the ring rotates.
**Before.** Size/stroke/track/caps ✓; ARIA ✓ (valuemin/max/now only when determinate). Deviations: stop dot moved with the arc head (wrong anchor point), dot radius was `max(t/2+1.5, 2.5)` (7px dot vs official 4dp), and at 100% the arc overlapped the dot (no reserved gap); indeterminate used a constant 65° arc + dashoffset comet (M2 pattern) instead of the M3 grow/contract.
**Required / implemented.** Determinate: `maxArc = c − 4 − thickness` so the spring fill always stops a 4px gap short; dot diameter = stroke thickness (4px default), fixed at `(cx, cy−r)`; indeterminate rewritten with `pathLength=1` + `strokeDasharray` keyframes `["0.15 0.85", "0.75 0.25", "0.15 0.85"]` (tween `easeInOut` — tween keyframes avoid framer's 3-keyframe-spring crash) over the same 1.5s the ring rotates linearly; added `ariaLabel` prop (default "Loading"); meta props/anatomy/states updated.
**Remaining limitations.** Officially the indeterminate cycle is driven by emphasized-curve head/tail springs; ours is a symmetric grow/contract approximation. Size tokens conflict across sources (Compose `Size = 40dp` vs 48dp commonly cited) — kept 48dp default per task/majority docs.

## 4. LoadingIndicator (M3E signature)

**Material spec (official `LoadingIndicatorTokens` / `LoadingIndicator.kt`).** Contained variant: 48×48dp container (`ContainerHeight/Width = 48dp`, rest shape `CornerFull`), `primary-container` container with `on-primary-container` active arcs (38dp active indicator inside); **global rotation = 4666ms** linear continuous full turn; **morph step = 650ms** (spring, damping 0.6 / stiffness 200); the shape morphs while the whole unit rotates.
**Before.** Colors ✓, counter-spinning arcs ✓, but default 56px, morph loop was a 3s hardcoded literal, rotation oscillated 0→45→0 instead of rotating continuously, `active=false` stopped at full opacity, and infinite loops ran regardless of `prefers-reduced-motion`.
**Required / implemented.** Default size 56 → **48** (official); morph duration 3s literal → `durations.extraLong4 × 0.65` = 650ms per step (token-derived, commented with the official constant); container now rotates **continuously 360°** on `durations.extraLong4 × 4.666` ≈ official 4666ms with per-value transitions (tween keyframes for borderRadius + linear rotate — documented framer crash pattern avoided); inactive state = static **circle at 38% opacity** (cross-cutting disabled/content opacity; the "40%?" from the brief resolved to 38%); `useReducedMotion()` gates all loops (reduced-motion users get the static full-opacity circle); meta updated (size 48, rotation anatomy, paused state, example sizes 48/72).
**Remaining limitations.** The official morph sequence walks a polygon morph list (circle → clover-like shapes) via springs; ours morphs `borderRadius` 50%↔24% with tween easing — visually close, not polygon-exact. Arc spin rates (1s / 1.6s counter-rotation) remain a token-multiplier approximation.

## 5. Snackbar

**Material spec.** `inverse-surface` container, `inverse-on-surface` text, `inverse-primary` text action, **4dp corners** (MDC `shape-radius: small`), elevation **level 3**, min-height 48dp, **min-width 344px / max-width 672px** (MDC Web M3 `$min-width/$max-width`), 4–10s timeout (default 4s), one at a time, `role=status` + `aria-live=polite`, close control (MDC: 18px icon on a 36px button), no leading icon in the base M3 anatomy.
**Before.** Colors, elevation 3, min-h-12, 4s default, role/status ✓, expressive y-spring ✓. Deviations: `rounded-lg` (8px) instead of 4dp; `max-w-sm` (384px) with no min-width (official 344–672); close button was a 26px target (p-1 + 18px icon); leading icon undocumented as an extension; demo could overlap its two fixed-position snackbars (violates "single at a time" legibility).
**Required / implemented.** `rounded-[4px]`; `min-w-[344px] max-w-[min(672px,calc(100vw-3rem))]`; close = `size-9` (36px, exact MDC) with 18px icon; action gets `min-h-9`; icon prop documented in meta as an extension (kept for API compat, per brief); demo stacks the second snackbar with `className="bottom-24"`.
**Remaining limitations.** No swipe-to-dismiss (optional in spec, noted for a future task); `duration={0}` sticky mode is a documented extension; the 4–10s range is guidance — the API accepts any ms (clamping would silently break callers, so meta carries the guidance instead).

## 6. Tooltip

**Material spec (official Compose tokens + MDC constants).** Plain: `inverse-surface`, **`CornerExtraSmall` (4dp)**, min-height 24dp, padding **4dp vertical / 8dp horizontal**, `body-small` `inverse-on-surface`, max-width **200dp**, **8×16dp caret**, 4dp gap to anchor. Rich: `surface-container` (verified on m3.material.io + `RichTooltipTokens.ContainerColor`), **`CornerMedium` (12dp)**, **level-2 elevation**, title-small + body-medium in **`on-surface-variant`**, `label-large` primary action (36dp min height), 320dp max width. Delays (MDC Web `constants.ts`): **show 500ms, hide 600ms**. Touch = long-press. No role on trigger; `aria-describedby` linkage expected.
**Before.** Plain was a `rounded-full` pill with 12/6px padding, no caret, no max-width; rich used `surface-container-highest` + `rounded-xl` + `on-surface` text, no border; delays were 400ms show / instant hide; hover/focus only (touch tap stuck the tooltip open); no `aria-describedby`; rich action was unclickable (`pointer-events-none` on the whole tooltip).
**Required / implemented.** Plain → `rounded-[4px] px-2 py-1 min-h-6 max-w-[200px]`; rich → `bg-m3-surface-container rounded-[12px] border border-m3-outline-variant m3-elevation-2` with `on-surface-variant` title/body and `min-h-9` primary action (now interactive: rich is `pointer-events-auto`, the 600ms hide delay lets the pointer cross the 4px anchor gap, whose spacing changed `mb-2/mt-2` → `mb-1/mt-1`); 8px rotated-square caret for both variants (borders on the rich caret to keep the outline continuous); show delay `durations.long2` (500ms), hide delay `durations.long4` (600ms), touch long-press on `durations.long2` with tap-to-dismiss; `useId` + `cloneElement` sets `aria-describedby` on element triggers, tooltip carries `role="tooltip"` + the id; meta anatomy/states/dos rewritten.
**Remaining limitations.** No viewport-edge flipping (placement is manual top/bottom, as before); caret is a plain rotated square rather than the exact 16×8 notch; `cloneElement` linkage only applies when the child is a valid element (documented pattern).

## 7. Banner

**Material spec.** Full-width bar, **square corners (shape none), elevation 0**, container **`surface-container-low`** (verified: Flutter M3 `MaterialBanner` default `backgroundColor = ColorScheme.surfaceContainerLow`), 24dp `on-surface-variant` leading icon, `body-medium` text, actions = text buttons **below the content above a divider, end-aligned** (Flutter M3 reference: `AlignmentDirectional.centerEnd` action bar, min action-bar height 52px; M2 right-aligned heritage), divider `outline-variant`.
**Before.** Container color ✓, icon/text/typography ✓, divider ✓, actions `justify-end` ✓ (end-aligned turned out to be correct). Deviations: `rounded-lg` (spec = none); action buttons were 36px with no 40dp text-button height; action row had no 52px min height; close button 28px target.
**Required / implemented.** Removed corner rounding (square, per spec); action row `min-h-[52px]` with 40dp (`h-10`) text buttons; close button `size-9` (36px target); meta anatomy rewritten (square corners/shape none, 24dp icon, 52px end-aligned action row, 40dp buttons). ARIA decision recorded: banner intentionally has **no landmark/`status` role** — it is a persistent, visually prominent surface message, not a live region (matches the official component, which defines none).
**Remaining limitations.** The optional trailing close icon is a kept extension (base anatomy = icon + text + actions); content padding (12px vertical) is slightly denser than Flutter's 24/4 rhythm, kept for page-scale balance.

## 9. Cross-component consistency notes

- **Disabled/content opacity = 38%** everywhere now (Badge; LoadingIndicator inactive). No `opacity-40` left in the family.
- **Motion**: every transition uses `@/lib/m3/tokens` — springs via the per-file `asTransition` shim (tokens.ts factory typing), loops via `durations.*` with documented multipliers that reproduce official constants (LoadingIndicator 4666ms rotation / 650ms morph; progress sweeps). No raw ms literals remain. Tween keyframes (not springs) are used for any 3-keyframe animation, per the recorded framer crash rule; LoadingIndicator uses per-value transitions (borderRadius tween / rotate linear / opacity short4).
- **Reduced motion**: the global CSS media block only covers CSS animations; LoadingIndicator additionally gates JS loops via `useReducedMotion()`. Other infinite loops (progress sweeps) are decorative under `role="progressbar"` and left running — a `MotionConfig reducedMotion="user"` at the app root (owned by the orchestrator) would cover them centrally.
- **Touch targets**: snackbar close 36px (MDC official), banner close 36px, banner actions 40dp buttons, snackbar action `min-h-9`. Compact feedback surfaces intentionally sit below the 48dp general target (matches official reference implementations).
- **ARIA decisions**: progressbars = `role=progressbar` with min/max/now only when determinate + default "Loading" label; snackbar = `role=status aria-live=polite`; LoadingIndicator = `role=status aria-label="Loading"`; tooltip = `role=tooltip` + `aria-describedby` on the trigger; dot badge = `aria-hidden`; banner = no role (not a landmark, not a live region).
- **Verification**: `bunx tsc --noEmit` filtered to the 9 assigned files → 0 errors; `bun run lint` → 0 errors project-wide (2 pre-existing warnings in other batches' files). No files outside the 8 assignments + 7 meta blocks were touched.
